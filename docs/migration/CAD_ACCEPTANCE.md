# Проверка CAD-экспорта

## Подготовка

Запишите дату, commit, версию Windows и версии SolidWorks и КОМПАС-3D.
Используйте отдельную пустую папку для проверки и сохраните тестовый проект.
Проверяйте новое приложение; для проверки поставки отдельно повторите сценарии
в установленной и portable-сборках. Для SolidWorks понадобятся шаблоны детали
`.prtdot`, сборки `.asmdot`, чертежа `.drwdot` и подключённая библиотека
материалов `.sldmat`. Для КОМПАС-3D можно использовать стандартный шаблон или
явно выбрать `.cdt`.

## Проверки в каждой CAD-системе

1. Создайте многослойный поддон с разными сечениями и сохраните проект.
2. Экспортируйте модель, выбрав подготовленную папку. Проверьте сообщения об
   успехе и повторный экспорт, не перезаписывающий первую папку.
3. Откройте детали и сборку: проверьте число деталей, размеры, ориентацию,
   взаимное расположение, материал и свойства массы. Форматы: `.SLDPRT` и
   `.SLDASM` для SolidWorks; `.m3d` и `.a3d` для КОМПАС-3D.
4. Создайте чертёж только сборки, затем чертежи деталей и сборки. Откройте их
   в CAD (`.SLDDRW` или `.cdw`) и проверьте ассоциативные виды, масштаб,
   габаритные размеры, спецификацию, количество деталей и технические требования.
   Для SolidWorks дополнительно сверьте размер листа, рамку и шрифты с выбранным
   `.drwdot` (включая встроенный или связанный формат `.slddrt`), а также
   размещение таблицы внутри листа. Если формат листа отсутствует, программа
   должна сообщить об этом вместо сохранения чертежа без рамки.
5. Измените проект в PalletLab, не экспортируя его заново. Повторно создайте
   чертежи из папки прежнего экспорта: спецификация и размеры должны относиться
   к сохранённым CAD-моделям, а не к изменённому проекту.
6. Проверьте отмену выбора папки, отсутствие установленной CAD-системы,
   неверный или отсутствующий шаблон и, для SolidWorks, неподключённую библиотеку
   материалов. Ошибка должна объяснять, что нужно исправить.

Запишите итог каждого пункта, используемые шаблоны, пути к тестовым материалам,
логи и скриншоты. Не используйте полученные чертежи для производства до проверки.

## Проверка сообщений об ошибках

Используйте сохранённую копию тестового проекта и отдельную пустую папку вывода.
Запишите исходные настройки CAD; не удаляйте и не переименовывайте настоящие
шаблоны, библиотеки, CAD-файлы или установленную CAD-систему. После проверки
верните исходные пути. Для сценария без установленной CAD используйте отдельную
виртуальную или тестовую Windows-машину, где эта система изначально отсутствует.

- Отмените выбор папки при экспорте и создании чертежа. Проверьте, что операция
  отменена, лишние файлы не появились и приложение продолжает работать.
- В тестовой копии настроек задайте несуществующий путь к шаблону SolidWorks,
  сохранив при необходимости остальные действующие пути. Запустите экспорт и
  проверьте результат: сообщает ли программа о проблеме либо использует
  настроенный в SolidWorks действующий шаблон по умолчанию. Зафиксируйте, какой
  именно шаблон использован; это предусмотренный резервный вариант экспортёра.
- Укажите несуществующую или специально созданную некорректную копию `.sldmat`.
  Проверьте понятное сообщение при выборе или чтении. Отдельно, при возможности,
  выберите существующую тестовую библиотеку, не подключённую в SolidWorks, и
  проверьте сообщение при экспорте. Настройки самой SolidWorks не меняйте ради теста.
- На отдельной машине без соответствующей CAD-системы попробуйте экспорт и
  создание чертежей. Запишите, объясняет ли ошибка, какая система или компонент
  отсутствует; основная программа должна оставаться работоспособной.
- Для каждого случая запишите версию приложения и CAD, шаги, текст сообщения и
  результат. При ошибке сохраните лог и скриншот; не считайте отсутствие ошибки
  подтверждением корректности, пока не проверен получившийся файл и путь шаблона.

## Сборка helper для разработчика

Нужен .NET SDK 10. На машине с SolidWorks по умолчанию используются его
redistributable interop DLL; для сборки без SolidWorks используется закреплённая
версия 32.1.0 двух сторонних NuGet-пакетов interop. Совместимость этого варианта
с установленной версией CAD нужно подтвердить реальным экспортом.

```powershell
dotnet publish tools/SolidWorksDrawingHelper/SolidWorksDrawingHelper.csproj -c Release -r win-x64 --self-contained true -o build/SolidWorksDrawingHelper
cd frontend
npm ci
npm run build
cd ..
.venv/Scripts/python.exe -m PyInstaller --noconfirm palletlab.spec
```

CI принудительно использует NuGet-вариант и упаковывает автономный helper.
PyInstaller намеренно завершится ошибкой, если helper не собран. Для проверки
готового пакета запустите `dist/PalletLab/PalletLab.exe --smoke-test`: тест
импортирует зависимости STEP, выполняет расчёт и проверяет наличие helper.
