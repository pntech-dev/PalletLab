# Протокол ручной приёмки: React viewport, проект и STEP

## Назначение

Этот протокол закрывает первый набор ручных проверок миграции: React/Three.js
viewport, базовые сценарии проекта и STEP workflow. Результаты переносятся в
[`MIGRATION_ACCEPTANCE.md`](MIGRATION_ACCEPTANCE.md).

## Перед началом

Заполните шапку прогона до запуска приложения.

| Поле | Значение |
| --- | --- |
| Дата и исполнитель | 09.11.2026 09:15 pntech |
| Версия приложения / commit | 0.5-beta last-commit: 91b9709200d51515557e8109eb1dc29ccbe90f23 |
| Windows | Windows-11 25H2 |
| Масштаб дисплея | 100%, для теста V-03 менял масштаб на 125% и 150% |
| Разрешение экрана | 2560x1440 |
| GPU / драйвер | GTX 1660 Super |
| Тестовый legacy-проект `.palletlab.json` | old.palletlab.json, new.palletlab.json |
| Обычная STEP-модель | test.STEP |
| Крупная STEP-модель | large_test.STEP |
| STEP с наклонной опорой | angle_test.STEP |

Перед проверкой соберите frontend и запустите web-клиент:

```powershell
Push-Location frontend
npm run build
Pop-Location
.venv\Scripts\python.exe src\web_main.py
```

Прогон выполняется для 125% и 150% DPI. Если доступен только один масштаб,
укажите это как ограничение результата.

## Критерий завершения

Прогон считается успешным, когда все применимые пункты имеют `✅`. Для каждого
`❌` создайте запись с ID пункта, средой, шагами воспроизведения и вложениями.
После успешного прогона перенесите дату, среду и подтверждение в соответствующие
строки `MIGRATION_ACCEPTANCE.md`. Не переводите их в `✅`, если не проверены оба
требуемых масштаба DPI либо ограничение не зафиксировано явно.
